# Project: Enterprise AI Operations & Access Control Agent

### One-line definition

> A secure enterprise AI agent that allows employees to interact with GitHub, Jira, databases, and operational systems through natural language, while **RBAC, permission-aware tool discovery, MCP, human approval, and audit logging** control what the AI is allowed to access or execute.

 ├── jira.issue.create
 ├── deployment.status.read

# PHASE 5 — Authorization Middleware
Now implement:

```
require_permission()
```
Conceptually:

```
@require_permission("github.issue.create")
```
The backend checks:

```
Who is the user?
       ↓
What roles?
       ↓
What permissions?
       ↓
Does required permission exist?
       ↓
ALLOW / DENY
```
Every protected operation should go through authorization.

# PHASE 10 — Permission-Aware Tool Discovery
This is one of the **key features of the project**.

Don't expose every MCP tool to every user.

Instead:

```
User
 ↓
RBAC
 ↓
Get permissions
 ↓
Filter MCP tools
 ↓
Allowed tools
 ↓
LLM
```
Example:

```
Developer permissions:

github.issue.read
github.issue.create
jira.issue.read
```
LLM sees:

```
search_github_issues
create_github_issue
search_jira_issues
```
It does **not** see:

```
delete_repository
production_rollback
database_admin
```
